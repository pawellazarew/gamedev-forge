# gamedev-forge

Конвейер, который позволяет ИИ-агенту вести разработку веб-игры без ручного
плейтеста на каждой итерации: агент **запускает игру, играет в неё ботами,
смотрит кадры, меряет производительность, читает баланс по сотням прогонов
и критикует результат**.

Собран за одну сессию (28.07.2026) по мотивам [The Long Silence](https://github.com/achimala/TheLongSilence)
(состязательный критик по скриншотам + Blender) и доклада Антона Чуева
«Сложности разработки игр с помощью AI» (автотест-бот, графики баланса,
редакторы вне билда).

## Что внутри

| Каталог | Что это |
|---|---|
| [`game-forge/`](game-forge/README.md) | конвейер: probe, shots, play, sim, analyze, report |
| [`blender-kit/`](blender-kit/README.md) | headless-Blender: спрайтшиты из 3D, превью моделей, BlenderMCP |
| `claude/agents/` | критики: визуал по кадрам, баланс по цифрам, вторые модели |
| `claude/skills/` | скиллы: game-forge, sprite-baking, blender-hardsurface |
| `fixtures/tiny-game/` | минимальная игра-фикстура: эталонный адаптер и smoke-тест CI |
| `docs/` | спецификации прототипов и журналы реальных прогонов |

## Быстрый старт

```bash
cd game-forge && npm install
node bin/forge.mjs doctor
node bin/forge.mjs all ../fixtures/tiny-game --runs 10
```

Установка агентов и скиллов в рабочий проект:

```bash
./install.sh /path/to/project     # копирует claude/* в <project>/.claude/
```

## Тесты

```bash
cd game-forge
npm run test:unit    # 58 тестов, без браузера, ~0.4 с
npm run test:e2e     # 14 сквозных на фикстуре, нужен Chromium
npm test             # всё сразу
```

Тесты регрессионные: почти каждый закрывает конкретную найденную ошибку —
смерти в знаменателе проходимости, зелёный отчёт при красном probe, путь
за пределы корня, `--runs` без значения, битый percent-encoding. Ломать
их «подгонкой под зелёное» бессмысленно: каждый описывает поведение,
которого не было и из-за которого выводы конвейера были неверны.

## Как это работает

**Три уровня доступа к игре.** Первый работает с любой веб-игрой сразу, третий
требует ~100 строк адаптера:

1. **Наблюдение** — `probe`: работа в кадре, ошибки консоли, вес, «живой ли кадр».
2. **Сценарии** — `shots` / `play`: кадры ключевых экранов с подсказками
   «что тут смотреть» + ассерты.
3. **Симуляция** — `sim` / `analyze`: боты играют сотни раз без рендера,
   ~1 млн игровых кадров в секунду, кривая сложности с доверительными интервалами.

**Замкнутая петля.** Кадры уходят агенту-критику (он действительно открывает
PNG), цифры — балансному критику, находки превращаются в правки, правки
перепроверяются тем же конвейером. Журнал каждой итерации — в `<игра>/.forge/JOURNAL.md`.

**3D → 2D.** `blender-kit` печёт спрайтшиты из моделей: ортокамера, N направлений,
кадры анимации, атлас + JSON под Phaser. Всё headless, значит повторяемо.

## Что конвейер измерить не может

Весело ли. Бот не скучает и не бросает игру; симуляция меряет проходимость,
а не удовольствие. `frameWorkMs` — это главный поток, без времени GPU.
Конвейер сужает круг до трёх мест, которые человеку стоит потрогать руками,
но живой плейтест не заменяет.

## Правила автономной сессии

- **Стоп-условие обязательно.** «Пока не станет красиво» недостижимо по построению.
- **Одна правка за итерацию** — иначе непонятно, что сработало.
- **Харнесс не трогаем.** Агент, который правит игру, не правит конвейер:
  иначе он «починит» тест вместо игры.
- **Сначала достоверность, потом выводы.** `bot-suspect` или таймауты >20%
  означают, что цифры баланса не значат ничего.
- **`wall` — это где встал бот, а не игрок.** Прежде чем объявлять стену
  дефектом игры, нужна абляция: политика, заточенная ровно под эту стадию.
- **Метрика без глаз врёт.** Зелёные числа совместимы с нечитаемым экраном.

Эти правила выведены не из общих соображений, а из ошибок, которые конвейер
допустил на реальных играх — они разобраны в `docs/examples/JOURNAL-*.md`.

## Проверено на

- **Brick Breaker** (vanilla canvas) — нашёл вечный цикл мяча: при точном
  центрировании ракетки партия не может закончиться (150 000 кадров, ноль прогресса).
- **REBOOT: Last Engineer** (Phaser 3) — нашёл четыре дефекта, запиравших
  экономику: неснимаемый кап ресурсов, самообнуляющиеся задачи роботов,
  нетикающее тех-дерево, цену постройки без зависимости от количества.
  При этом все 157 юнит-тестов игры проходили зелёными.
